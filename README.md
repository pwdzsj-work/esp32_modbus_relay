# ESP32 Modbus RTU 四路继电器/采集板

适用于所附 `SCH_Schematic1_2026-07-25.pdf`，可直接用 VS Code 的
Espressif IDF 插件打开。默认目标 `esp32`，建议 ESP-IDF 5.4/5.5。

## 原理图引脚

| 功能 | ESP32 引脚 | 有效状态 |
|---|---:|---|
| RELAY1..4（逻辑顺序） | GPIO27, 26, 25, 33 | 高电平吸合，已按 4→1 反向映射 |
| NQ1..4 | GPIO18, 2, 32, 23 | 光耦导通时读低，程序转换为逻辑 1 |
| NQ5..8（逻辑反馈顺序） | GPIO39, 36, 35, 34 | 继电器反馈，已同步反向映射 |
| ADS1115 | SDA=21, SCL=22, 地址 0x48 | ADS AIN3..0 对应板端 AN1..4 |
| RV-3028-C7 | SDA=21, SCL=22, 地址 0x52 | 与 ADS1115 共用 I²C 总线 |
| RS485 | TX=13, RX=14, 方向=19 | 485C低为发送、高为接收 |

## Modbus 默认参数

- 从站地址：1
- 9600 bit/s，8 数据位，无校验，1 停止位
- 支持功能码：01、02、03、04、05、06、0F、10、11
- 修改参数请编辑 `main/board_config.h`

### Qt/RS485/LoRa 设备扫描

Modbus 功能码 `0x11`（Report Server ID）可用于 RS485 或透明 LoRa
链路上的设备扫描。固件会判断请求来自 RS485 还是 LoRa，并从同一链路返回
响应。

扫描默认地址 `1` 的请求：

```text
01 11 C0 2C
```

设备在线时返回以下内容（末尾 CRC 由固件自动生成）：

```text
01 11 0F 01 FF 45 53 50 33 32 2D 52 45 4C 41 59 2D 34 FA 60
```

其中 `0F` 是后续数据字节数，`01` 是 Server ID，`FF` 表示设备正在运行，
后面的 ASCII 内容为 `ESP32-RELAY-4`。Qt 收到地址、功能码、长度和 CRC
均正确的响应后，将该地址标记为上线；连续若干次轮询超时后标记为离线。

修改 `BOARD_MODBUS_SLAVE_ADDR` 后，`BOARD_MODBUS_SERVER_ID` 会自动采用相同
地址。每个 LoRa 节点必须配置不同的从站地址。

### LoRa 串口透传驱动

独立驱动文件为 `main/lora_uart.c` 和 `main/lora_uart.h`。默认使用 UART1：

| 信号 | ESP32 引脚 |
|---|---:|
| LoRa RX（连接 ESP32 TX） | GPIO17 |
| LoRa TX（连接 ESP32 RX） | GPIO16 |
| GND | GND |

默认串口参数为 `9600 8N1`。初始化和收发示例：

```c
#include "lora_uart.h"

lora_uart_config_t config = lora_uart_get_default_config();
ESP_ERROR_CHECK(lora_uart_init(&config));

const uint8_t request[] = {0x01, 0x11, 0xC0, 0x2C};
ESP_ERROR_CHECK(lora_uart_send(request, sizeof(request),
                               pdMS_TO_TICKS(1000)));

uint8_t response[64];
int length = lora_uart_receive(response, sizeof(response),
                               pdMS_TO_TICKS(1000));
if (length > 0) {
    /* response[0..length-1] 是 LoRa 模块透传收到的数据 */
}
```

需要其他引脚或波特率时，在调用 `lora_uart_init()` 前修改 `config`。LoRa
模块与 ESP32 必须共地，TX/RX 需要交叉连接。

LoRa UART 和接收任务默认在 `app_main.c` 中初始化。收到数据后会以
十六进制打印完整内容，并将完整报文交给 Modbus 从站处理，例如：

```text
I (...) LORA_RX: Received 4 bytes
I (...) LORA_RX: 01 11 c0 2c
```

接收任务以 5 ms 串口空闲作为一帧结束条件，单次最多处理 256 字节。接收
处理位于 `main/lora_receiver.c`。CRC、从站地址和功能码正确时，固件执行
Modbus 请求并通过 LoRa UART1 原路回复。RS485 Modbus 继续使用 UART2，
两个链路互不占用对方的串口。底层 LoRa UART 驱动保存在
`main/lora_uart.c`。

`main/lora_periodic_sender.c` 中保留了每 2 秒发送一次的测试任务，但默认
未在 `app_main.c` 中启动，因此上电后不会自动发送。测试内容为：

```text
LORA_TEST\r\n
```

对应十六进制数据：

```text
4C 4F 52 41 5F 54 45 53 54 0D 0A
```

手动调用 `lora_periodic_sender_start()` 后，发送成功时输出：

```text
I (...) LORA_TX: Sent 11 test bytes
I (...) LORA_TX: 4c 4f 52 41 5f 54 45 53 54 0d 0a
```

发送周期通过 `LORA_TEST_SEND_PERIOD_MS` 修改，测试内容通过
`s_test_command` 修改。该自动发送仅用于通信测试，正式部署多节点 LoRa
网络时应停用，以免多个节点周期发送造成碰撞。

### SW3 Wi-Fi Web 配置与控制

SW3 使用 GPIO15，开关另一端接 GND。设备运行时将 SW3 连续接地 3 秒即可
启动 Web 模式，不需要重新上电或复位；不足 3 秒就松开不会触发。热点启动后
先松开 SW3，再次连续接地 3 秒会关闭热点和 Web 服务。每次长按后必须松开，
持续按住不会反复开关。原有 RS485、LoRa、定时任务和采集功能不受热点开关
影响。按键输入带 50ms 稳定电平确认消抖，短暂的接点抖动不会中断长按计时。

Web 模式启动后：

1. 手机或电脑连接热点 `Relay-WebConfig`；
2. 热点密码为 `12345678`；
3. 浏览器访问 `http://192.168.4.1`；
4. 页面可保存路由器 SSID/密码、控制四路继电器、用浏览器时间校准
   RV-3028，并实时显示 NQ1..NQ4，以及四路模拟量的 0–10V 电压值和按
   100Ω 采样电阻换算的 4–20mA 电流值。

路由器凭据保存在 NVS 中。连接路由器成功后，串口会打印设备获得的局域网
IP，Web 页面可同时通过该 IP 或热点地址访问。热点在 Web 模式期间保持开启，
即使路由器参数填错也可以继续通过 `192.168.4.1` 修改。

Web 页面可为每路继电器设置每日吸合和释放时间。定时配置保存在 NVS 中，
即使热点未启动或设备重启也会继续按照 RV-3028 时间执行；吸合时间晚于释放
时间时自动按跨午夜计划处理。启用定时的继电器会以定时状态为准，手动修改后
会在下一次约 1 秒的定时检查中恢复计划状态。

GPIO15 是 ESP32 启动绑带脚。SW3 只应把它接地，不要外接高电平驱动。建议
设备启动完成后再长按 SW3，避免改变 ESP32 上电时的绑带采样状态。

### 线圈（0xxxx，功能码 01/05/0F）

| 地址（协议偏移） | 常见显示地址 | 含义 |
|---:|---:|---|
| 0..3 | 00001..00004 | 继电器 1..4 的 NQ5..NQ8 光耦反馈，1=吸合，0=释放 |

### 离散输入（1xxxx，功能码 02）

| 地址（协议偏移） | 常见显示地址 | 含义 |
|---:|---:|---|
| 0..3 | 10001..10004 | NQ1..NQ4，外部光耦导通=1 |
| 4..7 | 10005..10008 | NQ5..NQ8，继电器反馈光耦导通=1 |

### 输入寄存器（3xxxx，功能码 04）

| 偏移地址 | 常见显示地址 | 含义/单位 |
|---:|---:|---|
| 0..3 | 30001..30004 | AN1..AN4 ADS1115 原始有符号值 |
| 4..7 | 30005..30008 | AN1..AN4 ADC 引脚电压，mV |
| 8..11 | 30009..30012 | 工程值 x100；电压档 1000=10.00V，电流档 2000=20.00mA |
| 12..15 | 30013..30016 | 当前软件量程：0=0-10V，1=4-20mA |
| 16 | 30017 | NQ5..NQ8 反馈的继电器状态位图，bit0..3 |
| 17 | 30018 | NQ 状态位图，bit0..7 |

### 保持寄存器（4xxxx，功能码 03/06/10）

| 偏移地址 | 常见显示地址 | 读写 | 含义 |
|---:|---:|---|---|
| 0x0100..0x0103 | 40257..40260 | R/W | AN1..AN4 软件量程，0=电压，1=电流 |
| 0x0104 | 40261 | R/W | 写入控制继电器；读取返回 NQ5..NQ8 反馈位图，bit0..3 |
| 0x0105 | 40262 | R | NQ 输入位图，bit0..7 |
| 0x0300 | 40769 | R/W | RTC 年，2000..2099 |
| 0x0301 | 40770 | R/W | RTC 月，1..12 |
| 0x0302 | 40771 | R/W | RTC 日，1..31 |
| 0x0303 | 40772 | R/W | RTC 时，0..23 |
| 0x0304 | 40773 | R/W | RTC 分，0..59 |
| 0x0305 | 40774 | R/W | RTC 秒，0..59 |

注意：部分主站软件要求填写“协议偏移地址”，此时填 0、0x0100 等；
另一些软件显示 00001/30001/40001 风格地址。

### RV-3028 实时时钟

RTC 每秒在串口打印一次：

```text
I (...) RTC: 2026-07-25 Sat 13:30:00
```

固件按普通不可充电备用电池配置 RV-3028：启用 LSM 备用电源切换、启用快速
边沿检测并关闭涓流充电。新装电池后仍需成功校时一次，以清除此前锁存的 PORF
掉电标志；此后只要备用电池电压和连接正常，主电源断开不会再使时间失效。
无效时间会立即告警，持续无效时最多每 60 秒重复提醒一次。

推荐使用功能码 10 一次写入全部 6 个 RTC 寄存器。以下 Modbus RTU 帧把
从站 1 的时间设置为 `2026-07-25 13:30:00`：

```text
01 10 03 00 00 06 0C 07 EA 00 07 00 19 00 0D 00 1E 00 00 9A C1
```

读取全部 RTC 寄存器：

```text
01 03 03 00 00 06 C5 8C
```

也可以用功能码 06 修改单个时间字段；完整校时时建议写 0x0300..0x0305，
固件会检查日期范围、自动计算星期，并在最后写入秒寄存器以同步 1 Hz 计数。

## SW2 与模拟量硬件注意事项

SW2 的四个开关没有连接 MCU 检测脚，所以固件无法自动识别档位。切换某路
SW2 后，还要把对应保持寄存器 0x0100..0x0103 写成相同量程，程序才能采用
正确单位换算。

原理图中每路 100Ω（R58/R26/R30/R29）的两端标为 `SWLx`、`SWRx`，而 SW2
闭合后把 `SWRx` 接回同一个 `SWLx` 输入节点。按图连接时电阻两端没有形成
对地电流采样回路，4-20mA 无法正常转换。建议 PCB 投板前改为：

1. 100Ω 精密采样电阻一端接输入 LVx，另一端接 GND；
2. SW2 只负责在电流档接入该 100Ω，电压档断开；
3. 27k/10k 分压仍从 LVx 送 ADS1115；
4. 电流换算以实测采样电阻和分压电阻校准。

当前代码按“100Ω 已正确对地接入 + 27k/10k 分压”计算：
`输入电压 = ADS电压 × 3.7`，`电流(mA) = 输入电压 / 100Ω × 1000`。

## 编译和烧录

```bash
idf.py set-target esp32
idf.py build
idf.py -p COMx flash monitor
```

上电初始化时四路继电器全部释放。GPIO2 是启动绑带脚，也是 NQ2；外围电路
必须保证复位采样期间不会把 GPIO2 拉低，否则 ESP32 可能无法从 Flash 启动。

## 文件结构

- `relay_driver`：四路继电器
- `digital_input`：NQ1..NQ8（含四路继电器反馈）
- `ads1115`：ADS1115 I2C 底层
- `analog_input`：量程、通道映射与工程值换算
- `modbus_slave`：RS485 Modbus RTU 从站
- `board_config`：所有引脚和通信参数
